Documentação

Cinco componentes e uma camada nativa, nos dois temas. Nada nesta página muda de código quando o tema troca — só os tokens.

Instalação #

Uma linha de CSS e uma de JavaScript. Sem build, sem package.json, sem dependência de runtime. A página precisa ser servida por HTTP — ES modules não funcionam em file://. 

<!doctype html>
<html lang="pt-BR" data-lc-theme="legacy">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <link rel="stylesheet" href="../lc.css" />
    <script type="module" src="../components/loader.js"></script>
  </head>
  <body class="lc">
    <div class="lc-page-body">…</div>
  </body>
</html>
class="lc" no <body> é o que aplica fundo, cor e tipografia do tema. Sem ela a página fica branca com Times New Roman.

O atributo data-lc-theme no <html> escolhe o tema: legacy reproduz o painel PHP (AdminLTE/BS3), modern reproduz o console React (Tailwind/slate). Sem o atributo, vale legacy. Os dois temas são carregados sempre — trocar é mudar um atributo, sem recarregar nada.

Regras de ouro #

São seis, e a primeira explica a arquitetura inteira do kit. Os selos classe e comp na navegação à esquerda marcam de que lado cada coisa está.

Botão, campo, card, alert, badge e tabela são CLASSE, não tag. Não existe <lc-button>; existe .lc-btn. Custom element só onde há comportamento. O alvo do kit é reproduzir telas que já existem em HTML simples: portar uma view do legado tem que ser renomear classe, não reescrever em componente.
  1. Nunca reestilize componente por dentro — use atributo, ::part() ou a custom property documentada.
  2. Tag custom nunca é self-closing. <lc-icon name="x"></lc-icon>, jamais <lc-icon /> — o parser engole o resto do markup.
  3. Nenhum valor literal de cor ou medida no protótipo. Use token (var(--lc-space-m)). Literal quebra na troca de tema, que é a razão de o kit existir.
  4. Textos de UI em pt-BR.
  5. Ícone sempre por <lc-icon>, nunca SVG inline nem emoji.

Botões classe #

O default é o .btn-default do legado (branco com borda), o segundo mais usado lá. O sólido de marca é .lc-btn--brand, o mais usado de todos.

Tamanhos e estados

Passe o mouse nas variantes sólidas: cada uma escurece para a própria cor (fill-loud), e as desabilitadas não reagem.

Campos classe #

.lc-field agrupa rótulo, controle e mensagem. .lc-field--error no grupo tinge a borda e libera o .lc-error.

Avisos e chips classe #

.lc-alert unifica o .alert e o .callout do legado, que eram a mesma coisa com ênfase diferente. .lc-alert--banner é o antigo callout, com a barra na lateral.

Tabela classe #

Modificadores: --striped, --hover, --bordered, --condensed. O menu de ações na última linha usa top layer, então não é recortado pela tabela.

lc-switch comp #

É cidadão do <form> nativo: entra no FormData, responde a reset() e participa da validação. Desligado não entra no FormData — igual ao checkbox nativo.

lc-dropdown comp #

placement: bottom-start (default), bottom-end, top-start, top-end. Fecha por clique fora e por Esc sozinho.

O painel abre no top layer nativo: não é recortado por contêiner com overflow, funciona dentro de modal e na última linha de tabela que rola, sem configuração e sem z-index. Era o bug estrutural nº 1 do legado.

lc-icon comp #

Com label o ícone é semântico; sem, é decorativo. Nome inexistente rende um marcador visível e um aviso no console — nunca um espaço vazio, que é como ícone quebrado passa despercebido.

O último tem nome inválido, de propósito.

lc-modal comp #

data-lc-modal="open <id>" abre e fecha sem uma linha de JS — é o que permite protótipo navegável. Fecha pelo ×, pelo fundo e por Esc; os três passam pelo mesmo lc-hide, que é cancelável e diz a origem em detail.source.

lc-toast comp #

Chamado por função, não por markup: lc.toast(mensagem, opções). Variantes brand, success, warning, danger, neutral. duration: 0 não fecha sozinho. Aparece acima de modal aberto.

Tokens #

Os valores abaixo são lidos do tema ao vivo, com getComputedStyle. Troque o tema no cabeçalho e a coluna de valor muda junto — é a prova de que o contrato é o que os componentes leem, não uma tabela de documentação que envelhece.

Token Valor no tema atual Uso
Todo token existe nos dois temas — o tools/check-contrato.mjs reprova se não. Um token que só um tema define é um buraco que aparece meses depois, na tela que ninguém estava olhando.

Eventos #

Todos borbulham e atravessam o shadow boundary — pode escutar no document.

Evento Origem detail
lc-change lc-switch { checked, value }
lc-select lc-dropdown — cancelável, mantém aberto { value, item }
lc-show / lc-after-show lc-modal, lc-dropdown —
lc-hide / lc-after-hide lc-modal, lc-dropdown — lc-hide cancelável { source }
