lc-bricks

Cinco componentes e uma camada nativa, nos dois temas. Nada nesta documentação muda de código quando o tema troca — só os tokens.

Instalação

Uma linha de CSS e uma de JavaScript. Sem build, sem package.json, sem dependência de runtime. A página precisa ser servida por HTTP — ES modules não funcionam em file://. 

<!doctype html>
<html lang="pt-BR" data-lc-theme="legacy">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <link rel="stylesheet" href="../lc.css" />
    <script type="module" src="../components/loader.js"></script>
  </head>
  <body class="lc">
    <div class="lc-page-body">…</div>
  </body>
</html>
class="lc" no <body> é o que aplica fundo, cor e tipografia do tema. Sem ela a página fica branca com Times New Roman.

Os dois temas

O atributo data-lc-theme no <html> escolhe o tema: legacy reproduz o painel PHP (AdminLTE/BS3), modern reproduz o console React (Tailwind/slate). Sem o atributo, vale legacy. Os dois temas são carregados sempre — trocar é mudar um atributo, sem recarregar nada.

Use o seletor no cabeçalho para alternar. A escolha fica guardada e vale para as outras páginas desta documentação.

Os dois temas são reprodução medida, não proposta de design. Nenhum valor neles foi inventado: cada um saiu do código do produto correspondente.

Como esta documentação é organizada

A navegação à esquerda separa o que é classe do que é comp. Não é decoração: é a regra de ouro nº 1 do kit, e ela decide como você escreve o markup.

Cada página é um arquivo carregado de verdade, com URL própria — dá para linkar uma seção específica e o botão voltar funciona.
